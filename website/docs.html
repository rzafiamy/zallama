Build, Run, and Integrate Zallama

Zallama wraps three separate C++ inference engines — llama.cpp, parakeet.cpp, and kokoro.cpp — behind one Python daemon and CLI. This page covers the full contract: compiling from source, the CLI commands, the memory eviction policy, systemd deployment, and the OpenAI-compatible API reference.

🚀

Quickstart

The installer compiles all three engines for your platform and registers Zallama as a systemd service. Run it with root access: 

git clone https://github.com/rzafiamy/zallama.git
cd zallama
sudo bash install.sh

No root access, or want to compile engines individually / customize build flags? See Compiling from source below.

🔧

Compiling & Installation

Compile the C++ binaries for your platform, then run the unified Python-based daemon wrapper. Each build script is independent, so you can rebuild a single engine without touching the others.

Step 1 build-ggml-llama.cpp.sh

Compile Llama Engine

Compiles llama.cpp with CUDA support. You must pass a tag or branch name (e.g. b4600). 

./build-ggml-llama.cpp.sh b4600
Step 2 build-ggml-parakeet.cpp.sh

Compile Parakeet ASR

Compiles the speech-to-text parakeet-server, copies shared libraries, and patches paths via patchelf. 

./build-ggml-parakeet.cpp.sh master
Step 3 build-ggml-kokoro.cpp.sh

Compile Kokoro TTS

Compiles the speech synthesis kokoro-server statically. ONNX Runtime is fetched and linked automatically. 

./build-ggml-kokoro.cpp.sh v0.1.0
Step 4 install.sh

Setup Zallama System

Initializes the Python virtual environment, registers symlinks and shell completions, and installs an always-on daemon service. Run with root access. 

sudo bash install.sh

CLI reference

Every part of the daemon can be driven from the command line. Try the interactive demo on the home page for a live replay of these commands.

Command Description
zallama serve Starts the daemon and its OpenAI-compatible gateway on http://127.0.0.1:11435 by default. Loads the registry and begins idle-sweep checks for the LRU eviction manager.
zallama pull <model> Downloads a model by preset ID (llama3.2:3b, kokoro:82m) or a direct Hugging Face repo/file path, using aria2c when available.
zallama run <model> Pre-loads a model server and drops you into an interactive chat session against it — useful for quick manual testing outside the API.
zallama ps Lists currently loaded model servers with their port, memory footprint, uptime, and last-used timestamp — plus a total memory summary.
zallama set <model> <key>=<value> Updates a model's registry parameters (e.g. reasoning=false, ctx_size=8192). Already-running models need a manual reload to pick up changes.
⚖️

Memory eviction policy

Zallama tracks a single memory budget (RAM/VRAM, configurable) shared across every loaded model server. When a new model is requested and there isn't enough headroom, the manager evicts the Least-Recently-Used server first — repeating until either enough memory is free, or every other model has been evicted.

How "recently used" is tracked

Every request that reaches a model server bumps it to the front of the LRU queue. Idle servers sink toward eviction; hot servers stay resident even under memory pressure.

When the budget itself shrinks

Lowering the configured budget while models are loaded triggers the same eviction loop immediately, freeing servers until total usage fits under the new limit.

🧪 Try it yourself: the interactive eviction visualizer on the home page simulates this exact policy in the browser — drag the budget slider and load models to watch the LRU queue play out.

Systemd service setup

Run Zallama as an always-on backend service that boots up automatically with your server. A root install.sh run registers this for you; otherwise, create the unit file manually:

/etc/systemd/system/zallama.service 
[Unit]
Description=Zallama — Local LLM Server
After=network.target

[Service]
Type=simple
User=cook
WorkingDirectory=/home/cook/Documents/Dev/Dev-ai/zallama
ExecStart=/home/cook/Documents/Dev/Dev-ai/zallama/zallama serve
Restart=on-failure
RestartSec=5

[Install]
WantedBy=multi-user.target

Activate

sudo systemctl enable --now zallama

Follow logs

journalctl -u zallama -f

OpenAI-compatible API reference

Point any OpenAI SDK, LangChain, or agent framework at Zallama by setting the base URL to your daemon's address (default http://localhost:11435/v1). Try each endpoint live in the API playground on the home page.

Endpoint Modality Description
/v1/chat/completions Text & Vision Standard chat completions, with streaming and thinking-block support for reasoning models. Accepts image_url content blocks for vision-capable models bound to an mmproj projector.
/v1/audio/transcriptions ASR Upload MP3, WebM, M4A, or FLAC audio; Zallama transcodes with ffmpeg and transcribes with a Parakeet-backed model. Supports verbose_json and word-level timestamps.
/v1/audio/speech TTS Synthesizes speech from text with a Kokoro-backed model and streams back an audio file (e.g. MP3).

Chat — cURL

curl http://localhost:11435/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{
    "model": "qwen3.5-4b-q4_k_m",
    "messages": [
      {"role": "user", "content": "Tell me a joke."}
    ],
    "stream": true
  }'

Transcription — cURL

curl http://localhost:11435/v1/audio/transcriptions \
  -F "model=tdt-0.6b-v3-q8_0" \
  -F "file=@speech.mp3" \
  -F "response_format=verbose_json" \
  -F "timestamp_granularities[]=word"

Speech — cURL

curl http://localhost:11435/v1/audio/speech \
  -H "Content-Type: application/json" \
  -d '{
    "model": "kokoro:82m",
    "input": "Hello world, this is a local voice generated by Zallama.",
    "voice": "af_bella"
  }' \
  --output speech.mp3
⚠️ Model IDs are registry keys: the model field must match an entry already pulled into registry.yaml via zallama pull. Requesting an unregistered model returns an error instead of a silent fallback.
