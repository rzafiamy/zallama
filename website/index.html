Own your AI.

Your models, your hardware, your rules.

Zallama is a small daemon that turns any .gguf model into a real, standing service on your machine — chat, vision, speech, embeddings, reranking, image generation — all speaking the OpenAI API dialect your tools already know. 🌱Why Zallama exists

Stop renting
intelligence.

Every time you send a prompt to a cloud API, you're renting intelligence — and handing over your data, your context, and your habits along with it. Your hardware is idle. Your bill keeps growing. And the model behind the curtain can change, get deprecated, or get more expensive overnight.

Zallama flips that. You decide which models load, how much RAM/VRAM they get, when they sleep, and who's allowed to talk to them. Nobody else's usage policy, nobody else's outage, nobody else's log retention.

This is what it looks like to own your AI.

🏠

Your data stays home

Prompts, documents, audio, images — everything is processed on your machine and never leaves it. The daemon binds to 127.0.0.1 unless you say otherwise.

⚡

Your hardware finally works

That GPU sitting idle becomes a chat, vision, speech and retrieval server. Models load on demand and unload when idle, so your RAM and VRAM go back to you.

🔌

Nothing else has to change

A real OpenAI /v1 surface — chat, embeddings, audio, images, streaming included. Any OpenAI SDK, LangChain or existing integration works with a one-line base-URL swap.

🎛️

You set the rules

Context size, GPU offload, memory budget, idle timeout, who gets a key — all YAML, all per-model, all hot-reloadable. No usage policy but yours, and no model that vanishes overnight.

🧠The principle

A router and a process manager — that's it.

Under the hood, Zallama is a dynamic router and process manager for your local GGUF models. Ask for a model, and it starts the right engine, routes your request to it, and unloads it after a period of inactivity.

Register, don't discover

Zallama never scans a folder and silently loads what it finds. A model has to be registered before it exists. Nothing runs, and no memory is claimed, until you say so.

Config, not code

Two YAML layers: a global config read at startup (ports, budgets, defaults), and a per-model registry reloaded on every request. zallama set edits it for you.

🚀Your first 5 minutes

Start the daemon, pull a model, talk to it.

This is the whole loop. Everything else on this site is a deeper look at one of these four steps.

1

Wake the daemon

zallama serve

Starts the controller on http://localhost:11435. It sits quietly until a model is requested.

2

Pull a model — it's now yours

# A friendly shorthand (from Unsloth's repo)
zallama pull llama3.2:3b

# Or any GGUF straight from HuggingFace
zallama pull unsloth/Qwen2.5-Coder-7B-Instruct-GGUF/Qwen2.5-Coder-7B-Instruct-Q4_K_M.gguf

# Speech-to-text, auto-registered as modality=asr
zallama pull parakeet:0.6b
3

Tune it to your hardware

zallama set llama3.2:3b n_gpu_layers=99 ctx_size=8192
zallama set qwen3.5-4b-q4_k_m reasoning=false   # skip thinking blocks
4

Talk to it

zallama run llama3.2:3b

That's it. A model running on hardware you control, answering only to you.

🎛️Modalities

One endpoint, every modality.

Each model declares what it is. Zallama picks the engine and the route. A request to the wrong endpoint gets a clear 400, never a crash.

💬

Text & reasoning

modality: text · llama-server
POST /v1/chat/completions POST /v1/completions

Any instruct or thinking GGUF. Streaming, tool calling, and reasoning blocks pass straight through. Speculative decoding via a baked-in MTP head roughly doubles decode speed.

zallama pull qwen2.5-coder:7b
zallama pull deepseek-r1:8b
👁️

Vision

modality: text + mmproj artifact
POST /v1/chat/completions

Register the base GGUF with its projector and send image_url content parts exactly as you would to OpenAI. Zallama passes --mmproj to the backend for you.

zallama add qwen2.5-vl-7b \
  ~/.zallama/models/qwen2.5-vl-7b-q4_k_m.gguf \
  --mmproj ~/.zallama/models/mmproj-qwen2.5-vl-7b-f16.gguf
🎙️

Speech-to-text

modality: asr · parakeet-server
POST /v1/audio/transcriptions

Upload any audio format — Zallama transcodes to WAV via ffmpeg. Use the multilingual Parakeet TDT v3 for 25 European languages with auto-detection.

zallama pull parakeet:0.6b   # English
zallama pull mudler/parakeet-cpp-gguf/tdt-0.6b-v3-q8_0.gguf  # multilingual
🗣️

Text-to-speech

modality: tts · kokoro-server
POST /v1/audio/speech

Kokoro-82M: 54 voices across 8 languages, returned as a WAV stream. Leave voice out and Zallama picks one matching the detected language of your text.

zallama pull kokoro:82m
🎨

Image generation

modality: image · sd-server
POST /v1/images/generations

Stable Diffusion 1.5, SDXL Turbo, FLUX and Qwen-Image via stable-diffusion.cpp. Set steps, cfg_scale and sampler once per model; the daemon fills them in.

zallama pull flux:klein
zallama generate flux:klein "a lighthouse at dawn" --output dawn.png
🔎

Embeddings, rerank & zvec

modality: embedding / rerank
POST /v1/embeddings POST /v1/rerank POST /v1/zvec/{name}/query

Everything for local RAG: an embedding model, a cross-encoder reranker, and zvec — an in-process HNSW vector store that embeds and searches by calling Zallama's own /v1/embeddings.

zallama pull nomic-embed:v1.5
zallama pull bge-reranker:v2-m3
zallama zvec create notes
🧠Memory-aware eviction

Your RAM and VRAM
go back to you.

Three mechanisms keep your machine usable. An idle sweep unloads a model after idle_timeout seconds of silence. A count cap (max_loaded_models) limits how many run at once. And a memory budget (mem_budget_gb) evicts least-recently-used models until the incoming one fits.

Each model's cost comes from its declared mem_gb. If undeclared, it's estimated from file size — an estimate that is frequently off by 100% or more. So measure it: 

# Predict the largest ctx_size that fits — writes nothing
zallama calibrate qwen3.5-4b-q4_k_m

# Measure by actually loading, then write ctx_size + mem_gb
zallama calibrate qwen3.5-4b-q4_k_m --probe --apply

Small, latency-sensitive services (ASR, TTS) can be pinned: true — pre-warmed at startup and exempt from both the idle sweep and eviction. A ~1 GB model turns a 780 ms round-trip into an 80 ms one.

🔐Security

          
Owning it means running it safely.

          
Safe for single-user local use out of the box — and more deliberate the further you push it outward.

        


        

          

            
🏠

            
Localhost by default

            
The daemon binds to 127.0.0.1. Nothing on your network can reach it until you change host — and if you do, set a key at the same time.

          

          

            
🔑

            
Hashed, expiring API keys

            
zallama apikey generates a 256-bit key, stores only its SHA-256 hash with an expiry, chmods the config to 600, and prints the key once. Verified with a constant-time compare.

          

          

            
🛡️

            
VPN first, proxy second

            
For remote access, prefer WireGuard/Tailscale — zero public surface. If it must face the internet, keep Zallama on localhost and put a TLS proxy in front that only forwards /v1/*.

          

        


        

          expose it deliberately
          
$ zallama apikey --expires 90d      # prints the key once — store it in your password manager
$ ZALLAMA_HOST=0.0.0.0 zallama serve
$ curl http://llm-box:11435/v1/models -H "Authorization: Bearer $YOUR_KEY"
